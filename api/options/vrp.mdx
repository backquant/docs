---
title: "VRP"
description: "Retrieve the Volatility Risk Premium — the spread between implied and realized volatility — for a given asset."
---

The Volatility Risk Premium (VRP) endpoint returns the difference between implied volatility (IV) — what the options market prices in — and realized volatility (RV) — what actually occurred over the same window. A positive VRP means IV exceeded RV: sellers of volatility collected a premium. A negative VRP (rare) means the market underpriced the move that followed.

Traders use VRP to evaluate whether selling volatility (via straddles, strangles, or covered calls) is statistically favorable in the current regime, and to calibrate dynamic hedging models that account for the realized/implied vol spread.

<Tip>
VRP is persistently positive across most assets over long periods — this is the structural edge that option sellers collect. However, VRP collapses quickly during vol spikes. Monitor the trend of VRP alongside the absolute IV level before entering short-vol positions.
</Tip>

## Endpoint

```
GET https://api.backquant.com/v1/options/vrp
```

## Query parameters

<ParamField query="symbol" type="string" required>
  The asset to query. Supported values: `BTC`, `ETH`.
</ParamField>

<ParamField query="window" type="number" default="30">
  Lookback window in days for calculating realized volatility. Common values: `7`, `14`, `30`. Implied volatility is matched to the same tenor.
</ParamField>

<ParamField query="limit" type="number" default="30">
  Number of historical data points to return. Maximum: `365`.
</ParamField>

## Request example

```bash
curl "https://api.backquant.com/v1/options/vrp?symbol=BTC&window=30&limit=90" \
  -H "X-API-Key: bq_live_your_api_key_here"
```

## Response fields

<ResponseField name="success" type="boolean" required>
  `true` when the request succeeds.
</ResponseField>

<ResponseField name="data" type="object" required>
  <Expandable title="properties" defaultOpen>
    <ResponseField name="symbol" type="string">
      Asset symbol, e.g. `BTC`.
    </ResponseField>
    <ResponseField name="window" type="number">
      Realized volatility window in days used for the calculation.
    </ResponseField>
    <ResponseField name="current_iv" type="number">
      Current ATM implied volatility as a decimal.
    </ResponseField>
    <ResponseField name="current_rv" type="number">
      Realized volatility over the past `window` days as a decimal.
    </ResponseField>
    <ResponseField name="current_vrp" type="number">
      Current VRP: `current_iv` minus `current_rv`. Positive = IV is elevated above realized; options sellers are compensated.
    </ResponseField>
    <ResponseField name="history" type="object[]">
      Historical VRP series, ordered by date descending.
      <Expandable title="properties">
        <ResponseField name="date" type="string">
          Date of the observation in `YYYY-MM-DD` format.
        </ResponseField>
        <ResponseField name="iv" type="number">
          ATM implied volatility on this date.
        </ResponseField>
        <ResponseField name="rv" type="number">
          Realized volatility (trailing `window` days) on this date.
        </ResponseField>
        <ResponseField name="vrp" type="number">
          VRP on this date: `iv` minus `rv`.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="meta" type="object" required>
  <Expandable title="properties">
    <ResponseField name="timestamp" type="string">
      ISO 8601 timestamp of when the snapshot was taken.
    </ResponseField>
    <ResponseField name="version" type="string">
      API version string, e.g. `1.0`.
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
All volatility values are annualized and expressed as decimals. A `current_vrp` of `0.18` means implied vol is running 18 annualized percentage points above realized vol — a historically wide spread that typically favors short-volatility strategies.
</Note>
