---
title: "Term Structure"
description: "Retrieve the implied volatility term structure showing how IV varies across expiry dates."
---

The term structure endpoint returns at-the-money (ATM) implied volatility for each available expiry date, letting you see how the market prices volatility across time horizons. A normal (contango) term structure shows rising IV with longer tenors; an inverted structure — where near-term IV exceeds longer-dated IV — often signals near-term event risk or elevated spot demand for protection.

Traders use the term structure to identify calendar spread opportunities, assess whether near-term vol is expensive relative to longer tenors, and time options entries and exits around known events.

<Tip>
Compare the term structure before and after major macro events (e.g. FOMC, ETF rebalance dates) to see how the vol curve shifts. A kink at a specific expiry usually indicates a scheduled catalyst.
</Tip>

## Endpoint

```
GET https://api.backquant.com/v1/options/term-structure
```

## Query parameters

<ParamField query="symbol" type="string" required>
  The asset to query. Supported values: `BTC`, `ETH`.
</ParamField>

<ParamField query="expiry_from" type="string">
  Start of the expiry date range in `YYYY-MM-DD` format. Defaults to the nearest available expiry.
</ParamField>

<ParamField query="expiry_to" type="string">
  End of the expiry date range in `YYYY-MM-DD` format. Defaults to the furthest available expiry.
</ParamField>

## Request example

```bash
curl "https://api.backquant.com/v1/options/term-structure?symbol=BTC" \
  -H "X-API-Key: bq_live_your_api_key_here"
```

## Response fields

<ResponseField name="success" type="boolean" required>
  `true` when the request succeeds.
</ResponseField>

<ResponseField name="data" type="object" required>
  <Expandable title="properties" defaultOpen>
    <ResponseField name="symbol" type="string">
      Asset symbol, e.g. `BTC`.
    </ResponseField>
    <ResponseField name="term_structure" type="object[]">
      Array of ATM IV values by expiry, ordered from nearest to furthest.
      <Expandable title="properties">
        <ResponseField name="expiry" type="string">
          Expiry date in `YYYY-MM-DD` format.
        </ResponseField>
        <ResponseField name="dte" type="number">
          Days to expiry at the time of the snapshot.
        </ResponseField>
        <ResponseField name="atm_iv" type="number">
          At-the-money implied volatility as a decimal.
        </ResponseField>
        <ResponseField name="atm_strike" type="number">
          Strike closest to spot used for the ATM reading.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="spot" type="number">
      Spot price of the underlying at the time of snapshot.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="meta" type="object" required>
  <Expandable title="properties">
    <ResponseField name="timestamp" type="string">
      ISO 8601 timestamp of when the snapshot was taken.
    </ResponseField>
    <ResponseField name="version" type="string">
      API version string, e.g. `1.0`.
    </ResponseField>
  </Expandable>
</ResponseField>
